contained_ a container runtime, from scratch

A Linux container is just a process wearing a disguise. This one is built by hand in Rust — namespaces, pivot_root, dropped capabilities, a seccomp filter — and it draws a tarot card for its hostname.

Under the hood

Six namespaces, minus the dangerous parts

A single clone() call with the right flags gives the process its own view of the system. Then the runtime deliberately takes power away from itself before handing control to your command.

CLONE_NEWNS · pivot_root
Its own filesystem
Bind-mounts the rootfs, pivots into it, and unmounts the old root. The container can't see the host filesystem at all.
CLONE_NEWUSER
Remapped identity
Unshares a user namespace; the parent writes uid_map/gid_map so uid 0 inside maps to an unprivileged range outside.
CLONE_NEWPID · NET · IPC · UTS
Its own everything else
Fresh PID table starting at 1, isolated network stack, private IPC, and its own hostname — the tarot card.
capabilities + seccomp
Teeth pulled
Drops ~20 capabilities (mknod, sys_admin, sys_boot…) and EPERMs risky syscalls like ptrace and TIOCSTI before exec.
